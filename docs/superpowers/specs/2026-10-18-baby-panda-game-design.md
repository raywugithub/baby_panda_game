# 熊貓成長記 — 設計規格

- 日期：2026-10-18
- 狀態：待審閱
- 工作名稱：熊貓成長記（正式名稱可再改）

## 1. 目的與共識

### 使用者明確提出的需求
- 一款 baby panda 成長的互動網頁遊戲，主角以女兒的熊貓娃娃為原型（照片：`IMG_7696–7699.HEIC`）。
- 玩家是 9 歲女孩，設計對象為 9 歲以上；不能無聊，要有有趣的元素。
- **遊戲沒有終點**，熊貓可以不斷成長。
- 裝置：手機（主要）與電腦都要支援。手機是 **iPhone，使用 Chrome 瀏覽器**（iOS 上的 Chrome 使用 WebKit 引擎，行為與限制等同 Safari）。
- 熊貓娃娃的名字叫「熊貓」，念法特殊：「熊」念一聲（像「兄」），「貓」念短促輕聲。
- 女兒喜歡的玩法：收集、裝扮布置、探險與故事、照顧養成（四者皆為核心）。小遊戲刷分不是重點。
- 方向選定：「熊貓的家」為骨架，嫁接無限冒險地圖與收藏冊的點子。
- 冒險採**直接遊玩的互動場景**，不是派出門等待計時器。
- 主線故事：「項圈的祕密」。
- 房間採**自由擺放**。
- 部署：GitHub Pages。

### 假設（使用者已同意）
- 單人遊玩，進度存在瀏覽器本機，不需帳號、不需伺服器。
- 成功標準：女兒會想每天回來看熊貓，玩幾週後仍有新東西可解鎖與探索。

### 設計原則
1. **熊貓就是那隻娃娃**：外觀、項圈、伸手要抱抱的姿勢都要認得出來。
2. **不給壓力**：熊貓不會死、不會一直難過；沒有連續登入獎勵、沒有限時活動、沒有會過期的東西；缺席不會被懲罰。
3. **永遠有下一個**：成長、項圈、地點、故事四條線都沒有上限。
4. **完全沒有付費**：所有貨幣只能在遊戲中獲得，沒有任何購買入口。
5. **9 歲不是幼兒**：要有謎題、選擇（墜飾搭配、料理組合）、創作（布置、拍照）與有梗的幽默，避免過度幼稚的文案與互動。

## 2. 主角：熊貓

### 外觀（依照片）
- 暖米灰色毛巾布質感的毛（**不是純白**），以細小毛邊表現毛茸茸感。
- 黑色淚滴形眼圈；琥珀／淺棕色眼睛，眼神溫柔。
- 黑色大鼻子，口鼻部略突出。
- 黑色耳朵；黑色手臂與腿，透過黑色肩帶在背後連成一圈；背部與臀部為米灰色。
- 一條米灰色小短尾巴。
- **招牌金色／米色鍊條項圈**，任何造型下都必須畫出來。
- 招牌姿勢：坐著，雙手向前伸要抱抱。

### 成長外觀
- 階段 1–4：身形逐步變大（縮放 0.80 → 0.90 → 1.00 → 1.05），比例從嬰兒般的圓滾逐漸變為少年。
- 階段 5 以後：體型固定，改以**光澤層級**表現成長：`光澤層級 = floor(階段 ÷ 5)`（階段 5–9 為第 1 層、10–14 為第 2 層…）。每一層讓毛色更有光澤，並在熊貓周圍加一圈更亮的閃光粒子；第 4 層以上只增加光環的星點數，不再改變毛色。

### 名字與聲音
- 遊戲內一律稱「熊貓」。第一版不做語音，使用合成音效（吃、笑、打呼、叮噹）與文字泡泡；**所有玩法不依賴聲音**。之後若加入真人念名，依「兄＋短輕聲」錄製。

## 3. 遊戲結構

### 3.1 畫面
手機直式為主，底部 5 個導覽按鈕：

| 按鈕 | 畫面 | 內容 |
|---|---|---|
| 🏠 家 | 主畫面 | 熊貓、房間、照顧操作、料理台、指標、信箱、日記 |
| 🪟 窗外 | 冒險地圖 | 向上延伸的小路與地點節點 |
| 👗 衣櫃＆布置 | 編輯 | 換裝、搭配組合、房間自由擺放 |
| 🎁 禮盒機 | 抽禮物 | 禮盒機與棉花糖小舖 |
| 📖 相簿 | 圖鑑 | 朋友卡、物品圖鑑、食譜、地點印章、回憶照片、熊貓日記 |

另有「設定」（從家的右上角進入）：音效開關、匯出／匯入存檔、加入主畫面說明與目前是否已加入、版本號。

電腦版：遊戲區域置中，寬度上限 480px，兩側留白並顯示背景裝飾；滑鼠操作與觸控相同（Pointer Events）。

### 3.2 核心循環（一輪 5–10 分鐘，隨時可停）
1. 打開遊戲 → 熊貓伸手要抱抱，表情反映心情。
2. 照顧（餵食／洗澡／玩耍／抱抱）→ 指標回升、補充**元氣**。
3. 到窗外選地點 → 進入互動場景探索。
4. 元氣不足時熊貓會說想休息、要照顧 → 回到第 2 步。照顧隨時可做，**永遠不需要等待**。
5. 帶回星砂與物品 → 禮盒機、布置、換裝、看相簿。

### 3.3 貨幣
- ⭐ **星砂**：照顧、冒險、小遊戲、朋友請求取得（數值見 4.5）。用於禮盒機。
- 🍡 **棉花糖**：禮盒抽到重複物品時轉換取得。用於棉花糖小舖直接購買指定物品。

## 4. 無限成長系統

所有數值為**初始值**，集中放在 `content/balance.ts`，依實際遊玩調整。

### 4.1 有效照顧
- 每種照顧對應一個指標：**餵食→肚子、洗澡→香香、玩耍→心情、抱抱→心情**。
- 照顧時若對應指標 **< 100**，就是「有效照顧」，給予完整獎勵（見 4.5）並讓指標 +25（上限 100）。
- 抱抱額外限制：每小時最多 5 次有效抱抱。
- 不是有效照顧時（指標已滿，或抱抱超過上限）：**只有反應動畫，沒有任何數值獎勵**。

### 4.2 成長值與門框刻度
- 成長值來源見 4.5。
- 第 n 道刻度的**單格**所需成長值：`25 + 10 × n`（n 從 1 開始）。累積門檻 = 前 n 格加總。

| 刻度 | 單格 | 累積 | 備註 |
|---|---|---|---|
| 1 | 35 | 35 | |
| 2 | 45 | 80 | |
| 3 | 55 | 135 | |
| 4 | 65 | 200 | |
| 5 | 75 | 275 | 進入階段 2 |
| 10 | 125 | 800 | 進入階段 3 |
| 15 | 175 | 1575 | 進入階段 4 |
| 20 | 225 | 2600 | 進入階段 5 |

- 每 5 道刻度升一個**成長階段**：階段 = `floor(刻度 ÷ 5) + 1`。
- 預估節奏（每天 2 輪、每輪約 3 次有效照顧＋1 個新地點＋1 次小遊戲，約 100 成長值／日）：約第 3 天到階段 2、第 8 天階段 3、第 16 天階段 4、第 26 天階段 5。

### 4.3 成長階段

| 階段 | 名稱 | 第一版解鎖 | 之後的版本 |
|---|---|---|---|
| 1 | 奶熊貓 | 起始 | |
| 2 | 圓滾滾 | 臥室、料理台、新食材 | |
| 3 | 小探險家 | 能力「🌳 爬樹」 | |
| 4 | 竹林勇者 | 能力「🌊 潛水」 | |
| 5 | 雲端旅人 | 稱號＋光澤 | 能力「🌬️ 乘風」 |
| 6 | 星光熊貓 | 稱號＋光澤 | 浴室 |
| 7 | 月影守護者 | 稱號＋光澤 | 能力「🔦 夜視」 |
| 8 | 傳說熊貓 | 稱號＋光澤 | 庭院 |
| 9+ | 自動產生 | 稱號＋光澤 | |

- 第 1–8 階使用上表的固定名稱；第 9 階起，稱號由「形容詞 × 名詞」組合產生（例如「午睡冠軍熊貓」、「彩虹收藏家熊貓」），以 `hash(存檔種子, 階段)` 決定，同一份存檔的同一階永遠相同。第一版詞庫：形容詞 30 個、名詞 30 個。
- 每升一階：熊貓做慶祝動畫、相簿自動存一張「成長紀念照」、送一個免費禮盒。
- 之後的版本補上 5–8 階的能力與房間時，存檔不需遷移，解鎖條件直接依目前階段判斷。

### 4.4 項圈金鏈
- 每次有效照顧 +1 環、每次完成地點（首次或重訪）+1 環。
- 起始 2 個墜飾欄位；每累積 50 環 +1 欄位，沒有上限。
- 項圈上可見的鏈環最多畫 24 環；超過後以「×N」數字表示，並讓鏈條每 100 環變粗一級、變亮一級（最多 5 級）。

- 重訪超過每天 3 次後仍可遊玩並拿到星砂與寶物，只是不再給成長值，讓「探索新地點」保持是最主要的成長來源。

## 5. 照顧與情緒

### 5.1 指標
- 三個指標 **肚子／香香／心情**，範圍 0–100。
- 隨真實時間下降：肚子 −4／小時、香香 −3／小時、心情 −5／小時；**下限為 30**，不會更低。
- **元氣** 0–100：每完成一個地點 −25（見 6.2）；每次有效照顧 +15；每小時自然回復 +10；上限 100。
- 離線期間的變化在下次打開時依時間差一次計算；時間差上限為 72 小時；時間差為負數（系統時間被往回調）時視為 0。

### 5.2 照顧互動（都要動手操作）
- 🍙 **餵食**（→肚子）：把食物拖到熊貓嘴邊。食物各有反應：竹筍糕（滿足地拍肚子）、草莓麻糬（臉頰變粉紅）、酸梅（「呸！」吐舌頭）、星空蘋果（眼睛冒星星）。3 分鐘內吃超過 3 個會打嗝冒泡泡，泡泡裡寫著她的夢。
- 🍳 **料理台**（階段 2 解鎖，屬於餵食）：把 2 種食材放進鍋子組合，做出料理後餵給熊貓。第一版 6 種食材、12 道食譜；組合不在食譜內時會做出「謎之料理」（熊貓吃了表情很複雜，但還是吃完）。發現的食譜收進相簿「食譜」分頁。食材來自冒險與禮盒。
- 🛁 **洗澡**（→香香）：手指在熊貓身上來回搓出泡泡，泡泡覆蓋率達 70% 就完成；洗完甩水，螢幕出現水滴效果。
- 🎾 **玩耍**（→心情）：三選一——丟球（她去追，有時會撿回奇怪的東西，例如一隻襪子或一封信）、彈竹葉琴（熊貓跟著節奏亂舞）、比賽瞪眼（先眨眼的輸，熊貓常常輸了還不服氣）。
- 🤗 **抱抱**（→心情）：點她伸出的雙手，她靠過來、冒出一排愛心。

### 5.3 情緒狀態
依下列**優先順序**判斷，取第一個符合的狀態：

| 順序 | 狀態 | 條件 | 表現 |
|---|---|---|---|
| 1 | 睡覺 | 當地時間 23:00–06:00，或離線超過 12 小時後剛打開 | 戴睡帽蜷在窩裡打呼；點她會醒來，伸懶腰，轉為下一個符合的狀態 |
| 2 | 想睡 | 元氣 < 25 | 打哈欠、揉眼睛，提示「抱抱我、餵我吃點東西」 |
| 3 | 撒嬌 | 任一指標 < 50 | 拉拉玩家、頭上冒出對應需求的小圖示（**可愛不可憐**） |
| 4 | 開心 | 三指標平均 ≥ 70 | 耳朵抖抖、尾巴搖、哼歌 |
| 5 | 普通 | 其他 | 一般待機動作，並隨機使用房間裡的互動家具 |

- 離線超過 24 小時回來：先顯示「你回來了！」歡迎畫面（熊貓跑過來抱住螢幕），送一個「我想你了」小禮物（30 星砂＋一封信），之後才進入一般狀態。沒有任何扣分或損失。

### 5.4 隨機小驚喜（第一版 8 種）
- 3 秒內被戳 8 下 → 假裝很忙，拿出一本書擋住臉（書拿反了）。
- 打噴嚏把自己往後吹翻滾，然後若無其事地坐好。
- 偷吃被抓包：玩家回到家畫面時有 10% 機率看到她正把食物藏到背後，嘴角還沾著碎屑。
- 抱抱後 30% 機率害羞：用手遮臉，耳朵變粉紅。
- 打嗝夢話泡泡（見 5.2）。
- 點項圈 → 墜飾依序叮噹作響，熊貓跟著搖頭晃腦。
- 熊貓日記：每天第一次打開時產生一篇（從句庫組合，引用前一天去過的地點或吃過的食物）；玩家可貼一張貼紙回應。
- 朋友來訪：每天最多一次，有 30% 機率某位朋友來家裡坐坐，熊貓會招待，朋友離開時留下一個小禮物（不限時，關掉也沒有損失）。

## 6. 冒險與故事

### 6.1 窗外地圖
- 直式畫面，一條彎曲小路往上延伸，每個節點是一個地點；可上下捲動，可回到已去過的地點。
- 首次完成一個地點後，從它延伸出 1–2 個新節點（各 50% 機率，以節點種子決定）。
- 節點狀態：未探索（亮）、已完成（蓋章，祕密找到時多一顆星）、需要能力（顯示能力圖示與鎖頭）。
- **保證**：地圖上永遠至少有一個「目前能力就能進入」的未探索節點。若生成結果使所有未探索節點都被鎖住，就把最新生成的一個節點改為不需能力。

### 6.2 地點場景玩法（約 2–4 分鐘）
- 一張由背景層組成的 SVG 場景，內有 4–6 個可點的熱點（樹洞、石頭、草叢…）。
- 每個地點包含：
  - 👋 一位朋友或路過的居民：對話與一個小請求（例如找東西、送食物）。
  - 💎 主要寶物：星砂、物品、食材或墜飾。
  - 🔍 一個隱藏祕密：仔細找的隱藏熱點，或一個小謎題（第一版 4 種：影子配對、順序謎語、找不同、密碼鎖——用場景中的線索推出 3 位數）。
  - 🎮 30% 機率出現 30 秒小遊戲（第一版 3 種：接星星、跳石頭過河、泡泡配對），**可跳過**，跳過不影響完成。
- **完成條件**：與朋友／居民對話，並找到主要寶物。
- **元氣**：進入地點需要元氣 ≥ 25，但元氣在**完成時**才扣除。中途離開不扣元氣；當次進度保留到完成或當地日期改變為止。元氣不足時，熊貓會說想先休息，引導回家照顧。
- 已完成的地點**每天（當地日期）刷新一次**：新的寶物位置與一個小事件，以 `hash(地點種子, 日期)` 產生。

### 6.3 地點來源
- **手工地點**（第一版 3 個）：竹林小徑、雲朵郵局、貝殼灣。依序為地圖最前面的三個節點（竹林小徑完成後固定延伸出雲朵郵局，雲朵郵局完成後固定延伸出貝殼灣，之後才開始生成），有專屬對話、謎題與主線線索。
- **生成地點**：由「地形 × 版型 × 天氣 × 地標 × 居民 × 怪事」組合。第一版內容量：
  - 地形 6 種（竹林、海邊、雲上、雪山、蘑菇森林、星空湖），每種 2 個場景版型
  - 天氣 5 種（晴、雨、霧、下雪、彩虹），以覆蓋層呈現
  - 地標 12 種
  - 怪事 20 種（決定該地點的獨特小事件與名稱片語）
  - 名稱組合例：「會唱歌的鹽湖」、「打呵欠的雲梯」、「下糖果雨的蘑菇林」
- **生成方式**：`seed = hash(存檔種子, 節點編號)`，以確定性亂數（mulberry32）產生。存檔記錄節點編號、父節點、狀態，以及**節點建立時的快照**（名稱、地形、版型、天氣、地標、居民、怪事的 id 與生成器版本 `generatorVersion`）。之後即使內容表擴充，已存在的地點也不會改變。
- **能力門檻**：生成時以 25% 機率為節點加上能力需求。**只從遊戲中已實作的能力抽取**（第一版：爬樹、潛水），包含玩家尚未取得的，讓她看到「長大以後能去」的地方。地形決定能力：竹林、蘑菇森林→爬樹；海邊、星空湖→潛水；雲上、雪山→不加門檻（之後的版本再對應乘風、夜視）。

### 6.4 朋友
- 第一版 4 位：郵差兔子「棉花」、糖果店狐狸「橘子」、說故事的烏龜「慢慢」、愛發明的刺蝟「咕嚕」。每位都有一條專屬小故事線（5 段，依好感度等級解鎖）。
- 好感度點數：聊天 +1（每位每天最多 3 次）、送禮 +5（送到喜歡的禮物 +10）、完成請求 +10。
- 等級：第 n 級的**單級**所需點數為 `20 × n`；等級沒有上限。相簿朋友卡顯示目前等級與進度條。
- 每升一級解鎖一段新對話；第 3、6、10 級解鎖朋友專屬家具；第 1–5 級依序解鎖專屬故事線第 1–5 段。
- 朋友寄信到家裡信箱：每天最多一封，內容不會過期，不讀也沒有損失。
- 生成地點的居民有 50% 機率是朋友之一，否則是「路過的居民」（只有對話，不累積好感度）。

## 8. 技術架構

### 8.1 技術選擇
- **Vite + TypeScript + Preact（含 @preact/signals）**，輸出純靜態檔案。
- 美術：程式繪製的 SVG（熊貓、場景、物品），不使用外部圖片素材與網路字型。
- 粒子效果（愛心、泡泡、星星）用 Canvas 2D，同時存在的粒子上限 60 個，Canvas 的裝置像素比上限為 2。
- 熊貓的每個會動的部件放在獨立的 `<g>`，只用 transform／opacity 做動畫；三指標等頻繁變動的數值以 signals 精細訂閱，只更新對應的元素，不重新渲染整個畫面。
- 音效：Web Audio API 合成。在第一次 `pointerdown` 事件中呼叫 `AudioContext.resume()` 解鎖；無法偵測 iOS 靜音開關，因此以遊戲內音效開關為準；音效失敗時靜默略過。
- 動畫：CSS transform／keyframes 搭配 requestAnimationFrame；尊重 `prefers-reduced-motion`（關閉粒子與大幅度晃動）。
- **觸控規則**：
  - 窗外地圖：`touch-action: pan-y`；房間布置區、照顧區、小遊戲區：`touch-action: none`。
  - 拖曳使用 `setPointerCapture`；長按門檻 300ms、移動容差 8px。
  - 全域 `-webkit-touch-callout: none; user-select: none`（輸入框除外）。
- **版面**：`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`；高度 `100dvh`；最大寬度 480px；左右邊距 16px；頂部與底部導覽加上 `env(safe-area-inset-*)`；不產生水平捲動；所有按鈕觸控區 ≥ 44px。只支援直式；橫放時顯示「把手機轉直」的提示（電腦版不受影響）。
- **PWA**：vite-plugin-pwa，`registerType: 'prompt'`。偵測到新版本時，在家畫面顯示「有新版本，點一下更新」；點擊後先強制存檔並建立備份，再啟用新版本並重新整理。預先快取全部建置產物（遊戲不依賴網路資源）。
- **部署路徑**：Vite `base: './'`；manifest 的 `start_url` 與 `scope` 都設為 `./`，以支援 `https://<user>.github.io/<repo>/` 子路徑。建置時把 git 短 hash 寫入設定頁的版本號。
- 效能預算：首次載入（gzip 後）< 500KB；女兒的 iPhone（以及 iPhone SE 2 同級的舊機種，若有）家畫面與地點場景維持 ≥ 50fps，不達標時優先降低粒子數，其次關閉陰影。
- 瀏覽器支援：**主要目標為 iPhone 上的 Chrome 與主畫面 Web App（iOS 16.4+）**；另支援 iOS Safari 16.4+、桌面 Chrome／Safari／Edge 最新版。Android Chrome 盡量相容，但不列為驗收條件。

### 8.2 模組

```
src/
  core/        純遊戲邏輯（不碰 DOM，可單元測試）
    state.ts       遊戲狀態型別與初始狀態（3.4）
    time.ts        離線時間計算、指標衰減、元氣回復、當地日期與每日結算
    care.ts        有效照顧判定與獎勵、抱抱上限、料理組合
    growth.ts      成長值、刻度、階段、稱號、光澤層級、項圈環數與欄位
    mood.ts        情緒狀態判定（優先順序）
    economy.ts     星砂、棉花糖、小舖
    giftbox.ts     禮盒抽選、重複轉換、每日免費
    rng.ts         mulberry32、hash、種子工具
    mapgen.ts      地圖節點生成、能力門檻、可進入保證、節點快照
    locationgen.ts 生成地點內容、每日刷新
    story.ts       主線章節與小傳說觸發
    friends.ts     好感度與等級
    save.ts        序列化、schemaVersion、遷移、備份還原
  content/     純資料：物品、食物、食譜、地點、朋友、對話、章節、稱號詞庫、日記句庫、balance.ts
  panda/       熊貓 SVG 元件：部件、表情、動作狀態機、換裝圖層
  ui/          Preact 畫面與元件（家、窗外、場景、衣櫃布置、禮盒機、相簿、設定）

```

- `core/` 只匯出純函式與型別，不讀取系統時間與亂數；時間（`now`）與種子都由呼叫端傳入，方便測試。
- UI 透過 signals store 讀寫狀態。

### 8.3 存檔
- **格式**：JSON，頂層有 `schemaVersion`（整數）。存檔體積目標：遊玩一年後 < 300KB。
- **位置**：
  - 主存檔：localStorage 鍵 `panda.save`。
  - 備份：IndexedDB 的 `backups` 儲存區，保留最近 3 份（每次寫入主存檔時，若距離上一份備份超過 10 分鐘，就新增一份）。
  - 照片與封存資料：IndexedDB。
- **控制體積**：主存檔中熊貓日記只保留最近 60 篇、信件保留最近 30 封，更舊的移到 IndexedDB 封存（相簿仍可瀏覽）。
- **寫入時機**：狀態改變後延遲 1 秒寫入；另外在 `visibilitychange`（變為 hidden）與 `pagehide` 時立即寫入一次。
- **讀取與還原**：載入時驗證結構。主存檔損壞或不存在時，依序嘗試最新的備份；成功就顯示「已從備份還原」。全部失敗才建立新遊戲，並把損壞資料保留在 `panda.save.corrupt` 供匯出。
- **版本**：`migrations[v]` 依序把舊版存檔升級到最新版；遷移前先寫一份備份。若讀到 `schemaVersion` 比程式還新（例如舊快取的程式碰到新存檔），進入唯讀模式：可以看但不寫入，並提示「請更新遊戲」。
- **iOS 資料清除限制**：iOS 的 WebKit（Safari 與 iPhone 上的 Chrome 都是）對「沒有加入主畫面」的網站，若 7 天沒有使用，可能清除 localStorage 與 IndexedDB（主存檔與備份會一起消失）。
- **iOS 主畫面與瀏覽器分頁的存檔是分開的**：從主畫面圖示開啟的遊戲擁有獨立的儲存空間，看不到在 Chrome 分頁中的進度，反之亦然。
- 對策：
  - 偵測 `display-mode: standalone`。在 iOS 上以瀏覽器分頁開啟、且**還沒有任何進度**時，第一個畫面是「把熊貓帶回家」引導：圖解 Chrome 的「分享 → 加入主畫面」步驟（iOS 16.4+），並提供「先在這裡玩」的選項。
  - 若在分頁中已有進度，引導畫面改為「搬家」流程：先複製存檔碼 → 加入主畫面 → 從主畫面圖示開啟後貼上存檔碼。主畫面版第一次開啟時，若沒有存檔，會詢問「要搬家嗎？貼上存檔碼」或「開始新遊戲」。
  - 尚未加入主畫面時，在家畫面角落常駐一個小提示（可收合，但不會永久消失）。
  - 尚未加入主畫面、且距離上次匯出超過 5 天時，打開遊戲會溫和提醒「幫熊貓備份一下」。
  - 呼叫 `navigator.storage.persist()` 作為額外保護，但不依賴它。
- **匯出／匯入**：下載 `.panda` 檔案（JSON），或複製／貼上存檔碼（壓縮後的 base64）；匯出內容不含照片。iOS 上以 Web Share API 分享檔案，不支援時顯示存檔碼。
- 所有 storage 存取都包在 try/catch；寫入失敗時遊戲照常進行，並在頂部顯示「目前無法存檔，請匯出備份」。localStorage 寫入時若主存檔已超過 1MB，就提示匯出備份並先執行封存。

### 8.4 部署
- 原始碼放在 GitHub repo，透過 GitHub Actions 建置並部署到 GitHub Pages（推送到 `main` 時觸發）。
- 免費 GitHub Pages 需要公開 repo（或 GitHub Pro 才能用私人 repo）。網址可公開存取，但不會被主動列出。
- **隱私**：娃娃照片（含家中環境與手部）**不放進 repo**，`.gitignore` 排除 `*.HEIC` 與原始照片；遊戲中的熊貓完全由 SVG 繪製。

## 9. 時間與每日規則
- 「當地日期」以裝置時區的 `YYYY-MM-DD` 表示。
- 存檔記錄 `lastDailyDate`。打開遊戲時，若當地日期**大於** `lastDailyDate`，就執行每日結算（免費禮盒、地點刷新、日記、朋友信件與來訪判定、重訪成長計數歸零），並更新 `lastDailyDate`。
- 若當地日期小於或等於 `lastDailyDate`（日期被往回調、或跨時區），不執行每日結算，也不重複發放。

## 10. 錯誤處理

| 情況 | 處理 |
|---|---|
| localStorage 不可用（無痕模式等） | 用記憶體狀態繼續玩，頂部顯示無法存檔的提示與匯出按鈕 |
| 存檔損壞 | 自動從備份還原（見 8.3） |
| 存檔版本比程式新 | 唯讀模式，提示更新（見 8.3） |
| 匯入格式錯誤 | 顯示「這個存檔碼看不懂」，不覆蓋目前進度 |
| 匯入前 | 先確認「會取代目前的熊貓」，並自動備份目前存檔 |
| 系統時間往回調 | 時間差視為 0；不執行每日結算（見 9） |
| IndexedDB 不可用 | 不建立備份；拍照模式可以拍，但照片無法保存，並提示原因 |
| 拍照輸出失敗 | 降低解析度重試一次，仍失敗則提示再試 |
| 音效無法初始化 | 靜默略過，玩法不受影響 |

## 11. 測試

- **單元測試（Vitest，TDD）**：`core/` 全部模組。重點：
  - 有效照顧判定、抱抱每小時上限、指標 +25 上限、非有效照顧無獎勵
  - 指標衰減與下限 30、元氣回復與上限、72 小時上限、時間倒退
  - 刻度門檻（對照 4.2 表格）、階段計算、第 9 階後稱號確定性、光澤層級
  - 項圈環數與欄位
  - 情緒狀態優先順序（每種組合）
  - 禮盒稀有度分佈（固定種子下的統計測試）、池內均等、重複轉換、每日免費
  - 每日結算：跨日、日期倒退、跨時區
  - 地圖生成確定性（同種子、同內容版本 → 同結果）、手工地點順序、能力門檻只用已實作能力、「永遠有可進入節點」保證、節點快照不受內容表變動影響
  - 重訪成長每日上限、元氣完成時才扣
  - 主線章節觸發表、小傳說
  - 好感度等級公式
  - 存檔往返、遷移、備份還原、唯讀模式、日記與信件封存
- **元件測試**：照顧手勢判定（洗澡覆蓋率 70%、食物拖到嘴邊的判定區）、房間擺放碰撞與彈回、料理組合。
- **端對端（Playwright，Chromium 與 WebKit）**：手機尺寸與桌面尺寸各跑：新遊戲 → 抱抱 → 餵食 → 完成竹林小徑 → 開禮盒 → 擺一件家具 → 重新整理後進度仍在。另測「狀態改變後立即觸發 visibilitychange，重新載入後進度仍在」。Playwright 只作為回歸測試，不能代表 iOS 真機行為。
- **真機測試矩陣**：女兒的 iPhone（iOS 16.4+），分別在「Chrome 分頁」與「從 Chrome 加入主畫面」兩種模式下測試（另以 iOS Safari 分頁抽測），項目包括：「把熊貓帶回家」引導與存檔碼搬家流程、音效解鎖、離線開啟、新版本更新提示與更新後存檔、拍照存入遊戲相簿、切換 App 後存檔保留、安全區域與瀏海、效能（≥ 50fps）。
- **實際遊玩測試**：請女兒試玩，觀察卡關點、無聊點與最喜歡的互動，調整 `balance.ts`。
